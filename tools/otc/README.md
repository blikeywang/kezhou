## 5. 公开数据契约

### 5.1 顶层

`schema=traderhome_otc_daily_v1`；`sourceMode=user_notion_with_authorized_reference_archive`。

| 字段 | 含义/不变量 |
|---|---|
| `dataDate` | 最新已接收资料日，不是访问日；等于公开点的最大日期 |
| `checkedForDate` | 本次核验针对的日期，可能晚于资料日 |
| `generatedAt` | 产物生成/核验时间，不是市场报价时间 |
| `startDate` | 实际公开历史起点 |
| `source` | 最新原页规范 URL，去掉复制链接参数 |
| `recordCount` | `sum(len(asset.points))`，不是当日原页条数 |
| `assets` | id、sector、mapping、升序 points；同一 id/date 唯一 |
| `days` | 用户原页每日上下文；参考历史没有原页上下文时不编造 |
| `referenceArchive` | 归档来源、抓取时间、冲突数量、优先级和节点接口限制 |
| `privacy` | accounts、credentials、paidOriginalText、rawBrokerBars 全为 false |
| `method` | 研究方法版本、缺失处理、非回测/非执行边界 |

### 5.2 每个历史点

| 字段组 | 字段与解释 |
|---|---|
| 原始数值 | `date, otc, burst, cycle, day, unit`；单位为天或月；day 表示来源计数，不是程序累加结果 |
| 日差 | `otcDelta, burstDelta, deltaReferenceDate, deltaDays`；后两项明确比较哪一天、间隔多少自然日 |
| 历史评级 | `quality, qualityNote`；项目记录，不是作者保证；无节点一般沿用原评级 |
| 来源 | `source, sourceKind, sourceAsOf, sourceCheckedAt`；`sourceAsOf`通常是页面编辑时点，不是首次可获知时点 |
| 周期与节点 | `previousDate, gapBefore, transition, node, legacyNode, unconfirmedNode` |
| 阈值 | `thresholdEvents, thresholdCandidates`；确认事件与跨缺页/换源候选分开 |
| 警告 | `dataWarnings`；可选 `referenceConflict`；旧异常和来源冲突不可丢弃 |
| 作者提示 | `approaching`：原页写“逼近”才 true，不根据数值自行估计 |

允许旧历史出现 `day=null`：必须显示“周期天数/月数缺失”，不能改成 0、1 或推成新周期。新页缺字段应隔离不完整行并明确覆盖范围，不伪造全量；加入新资产或部分页需单独审核，旧日期脚本的固定 49 项断言不是永久 schema。

普通新增原页点的白名单为上述 26 个基础字段（不含 `referenceConflict`）；新增键必须有明确用途和公开性审核。不能把整个 Notion 响应塞进 `qualityNote` 或 `dataWarnings`。

### 5.3 每日上下文与潜力区

`days[]` 只包含：`date, source, flowSum, flowHeadline, flowWarning, potential, review, zones`。

公开 `zones[]` 白名单：`asset, zone_type, zone_label, level, venue_mapping, source_date, valid_through, note`。更完整的交易所映射、原始文字和监控审计留在私有研究项目，不因公开摘要省略而宣称已经核实。

## 6. 日期、日差、缺页与周期

### 6.1 日期裁定

1. 年份、页首日期、页面编辑时间、用户发送语境、前一原页都要核对。
2. 编辑时间不是资料日期，收到页面的当天也不必等于资料日。
3. 页首疑似漏改时，先保存原文并询问；周期天数只能提供旁证，不能自行定日。用户已经确认的历史更正：10月17日页首漏改、10月19日页首漏改，均按用户确认归档。
4. 保存 `source_page_date_text`、`resolved_data_date`、确认依据及核验时点。不用下一份页面倒推并悄悄改写前页。
5. 浏览器“今天”按 `Asia/Singapore`。加密日K仍按 UTC，股票按交易所时区，不混成同一个交易日定义。

旧私有 CSV 的日期仅有 `M.D`，全量构建路径曾显式按 2026 映射并拒绝其他年份；**跨年必须先迁移/确认年份，不能复制这段假设到 2027**。

### 6.2 日差与节点百分比

对同一来源序列的上一可用原页 `q` 和当前 `p`：

```text
otcDelta   = p.otc   - q.otc
burstDelta = p.burst - q.burst
deltaDays  = date(p) - date(q) 的自然日数
deltaReferenceDate = q.date
step_pct   = 100 × (当前节点场外 / 比较基准场外 - 1)
```

- 不除以 `deltaDays`；相隔两天的差额不能叫“单日涨跌”。
- 参考站补入的日期不改变原 Notion 日差基准。`previousDate`（合并图的前一条）与 `deltaReferenceDate`（来源日差基准）可以不同。
- 缺前值时用 null，不用 0。百分比基准为 0 或未知时不可计算，标记待核，不能无穷大或任选基准。
- 当前审核脚本记录百分比至小数点后 6 位，展示 2 位；独立复核使用 Decimal。不要拿显示舍入值做阈值判断。
- 旧历史自带的 Δ 与实际差额相差超过 0.11 时，旧导出器/测试要求警告而不是静默纠正。**0.11 是历史兼容容差，不是新数据精度目标**；新整数指数应精确相减。

### 6.3 连续性与周期切换

`adjacent = 日期恰好相差 1 个自然日`；`same_source = sourceKind 相同`；质量节点还要求 `same_cycle`。

- `gapBefore=true`：合并历史前后不相邻。缺页不填数，图上断线/斜纹。
- 原页未注明交易日计数规则时，周末不是自动补齐节点的理由。相隔周五和周一仍是跨自然日，不确认跨缺页节点。
- `transition` 表示相邻已有记录的周期标签不同；跨缺页只能说“观察到周期不同”，不能确定缺页中的切换日。
- 明确新周期按原文保留首日并把**新周期**质量重置待定；不能把旧周期评级带过来。只有周期发生变化但首日缺失时，首日基线未知。
- 同周期日计数通常应增加日历间隔，这只是异常检测；不一致时保留原值并记录“若按自然日预期值”。月计数不按天加一。

## 7. 阈值状态、阈值事件、质量节点：三者不能混用

| 类型 | 精确条件 | 结果 |
|---|---|---|
| 低位状态 | 当前 `otc < 1000` / `burst < 200` | 徽标和对应彩色点；可能连续很多天 |
| 新场外下穿 | 前值 `otc >= 1000` 且当前 `< 1000` | 相邻同源记 `thresholdEvents`，否则记候选 |
| 新爆破下穿 | 前值 `burst >= 200` 且当前 `< 200` | 同上；不要求周期相同 |
| 进场质量节点 | 相邻、同源、同周期为进场，前值 `burst > 200` 且当前 `< 200` | `node=跌回200` |
| 退场质量节点 | 相邻、同源、同周期为退场，前值 `burst < 0` 且当前 `> 0` | `node=负转正` |

边界例子必须保持：

- `200 → 199`：是爆破下穿事件，**不是**严格 `>200` 的进场质量节点。
- `201 → 200`：两者都不是；等于 200 不是低于 200。
- `-1 → 0 → 1`：现有规则没有一次相邻的严格负转正，不擅自把 0 跳过去确认节点。
- `195 → 165`：持续低于 200，不重复造节点。
- `-31 → -7`：仍负，不是负转正。
- `999 → 1001`：重新超过 1000，不是进场标签切换，不自动升级评级。
- 跨缺页/换源看到两端下穿：`thresholdCandidates`，不能声称知道发生日。
- 旧 CSV 标注过节点但不满足连续性：保留 `legacyNode`，`node=null`、`unconfirmedNode=true`；不追认。

`legacyNode` 是历史标记，不是强于新验证的证据。相邻阈值事件本身也不等于评级升级。

## 8. 质量评估：原规则与实际落地

### 8.1 作者规则的方向性含义

- 进场：本轮首日 → 第一个爆破跌回200节点 → 后续节点；节点场外值持续、明显上升，来源认为进场质量更好；持平、下降或反复则变差。
- 退场：本轮首日 → 第一个负转正节点 → 后续节点；节点场外值持续下降，来源认为退场/做空周期质量更好；不降反升或反复则变差。
- 进场第一周爆破未突破200、且动能均值不升反降，是来源提出的低质量警示。
- “明显”“连续几次”“均值窗口/斜率”等没有完整统一数值定义；不能凭空补 5%、两次、七个可用样本等自动升级公式。

### 8.2 当前维护政策

评级在审核/入库时写入，浏览器只展示。当前仓库**没有一个可对全部历史重算的通用评级服务**；不要把 `tier()` 当评级算法。

1. 没有新质量节点：沿用前一期质量。普通日涨跌、过千、爆破上穿200不重评。
2. 新周期：待定。首日缺失或周期身份不清，明确保留不确定性。
3. 新节点比较基准：同一周期中最近的**已确认、同源、非跨缺页**节点；若没有，则本轮已知首日。候选节点不能作“已确认前节点”。找不到基准则无法判定，不猜。
4. 本轮第一个已确认节点：计算与首日的差额并提示有利/不利，仍保留待定；“待定”不等于安全。
5. 后续已确认节点：进场节点不再上升、退场节点不再下降，降为或保持存疑。原历史可能含劣质标签，不对旧值批量映射成存疑。
6. 有利的两端比较若仍有缺页、计数异常、首日/周期不清，不自动升为优质；完整路径未验证就是未验证。
7. 没有明确完整的优质升级规则时，输出比较证据并保留待定/存疑；需要另行确认规则版本，不能靠 AI 主观印象自动升级。
8. 一周规则只在来源连续、窗口及均值口径可复核时作为审核警示；现有前端没有自动滚动均值判级实现。第4天不能提前套一周规则，缺页也不能用前值填满7天。

### 8.3 可独立复算的实际例子（全部为 2026-11-07）

| 标的 | 新节点 | 场外比较 | 算式结果 | 实际处理 |
|---|---|---|---:|---|
| ETH | −7→18 负转正 | 678 vs 10月16日已确认节点856 | `100×(678/856−1) = −20.794393%` | 两端有利，但旧缺页未清，待定；提示反弹风险 |
| BNB | −11→12 负转正 | 668 vs 11月4日668 | `0%` | 未继续下降，待定→存疑 |
| Spcx | −105→2 负转正 | 923 vs 11月4日977 | `−5.527124%` | 旧计数和映射未核实，仍待定 |
| Msft | 228→120 跌回200 | 752 vs 11月5日首日792 | `−5.050505%` | 首个确认节点仍待定，但进场比较不利 |

## 9. 观察列表排序与“这一天，怎么看”

以[当前 engine.mjs](../../portal/vendor/otc/engine.mjs)为准，`tier()` 顺序如下（先匹配先返回）：

1. 无点 → `missing` / 未覆盖。
2. 进场 + 优质 + 场外≥1000 + 爆破>0 → `focus` / 优先复核。
3. 劣质，或场外<1000，或爆破<0 → `avoid` / 谨慎回避。
4. 进场 + 有限日计数≤3 + 单位天 → `new` / 新周期。
5. 其余 → `watch` / 一般观察。

列表排序是 `focus → new → watch → avoid → missing`，同层按 id 排序。这里**没有资金加权、收益预期、综合胜率分数**；`存疑` 单独并不总返回 avoid。层级本身也没有新鲜度过滤，所以过期点仍可显示“一般观察/新周期”，必须同时阅读全局缺源横幅和计划阻断项，不能把列表标签当交易许可。

`planFor()` 的判断次序：

- 没有此前记录：不使用未来点解释今天。
- 单位月：只作为月度背景。
- 进场且场外<1000：强度不足；否则劣质回避追涨；否则优质且爆破>0才是多头研究优先；其余待确认。
- 退场：爆破>0提示反弹风险，否则等待结构；退场劣质是做空周期质量差，不是公司基本面差。
- 所有分支恒为 **`executable:false`**。恒列可成交价格/价格结构/止损、独立体系和账户风险许可未确认；旧源、缺页、缺链接、映射未核实及所有 `dataWarnings` 也加入阻断原因。

研究顺序是：**先新鲜度 → 再周期背景 → 再节点质量 → 再反证/背离 → 再独立价格结构与风险门槛**。不能反过来先选想做的交易，再挑数据解释它。

原研究项目的板块背景是另一层：选定篮子进场记 +1、退场记 −1，`score=sign(sum)`，平衡为0；没有覆盖也可能为0，须看 evidence 区分。当前例：加密篮子 BTC/ETH/SOL，AI应用 Msft/PLtr，AI存储 海力士/三星/Sndk/Mu，AI光模块 GLW/Aaoi/Axti。篮子不是自动取所有同行业资产，也不是强度加权。这个背景不进入当前 `tier()`，不能伪称网页已整合完整 S1/趋势/账户评分。

## 10. 资金、期权与来源观点的分析边界

### 10.1 资金明细

统一记录原页单位，当前 `flowSum/flowHeadline` 为**亿美元**。具名明细用 Decimal 加总，原页总述独立保存；数字为负不直接改写作者文字。

11月7日示例：BTC−2、ETH−1、SOL−0.7、ZEC−0.2，合计−3.9；总述−0.2。两者方向都为流出，**金额、时间和统计范围未对齐**，必须保留 `flowWarning`。该页新增ZEC，不能和上一页不同篮子的合计直接比较为“资金改善”。

### 10.2 “比特币Vega”与真实期权风险

`比特币Vega` 是原页研究标签，它的场外/爆破值不是交易所 IV，也不是持仓 Vega。原页“Delta/Gamma 中性、Vega 负、iron condor”等只作来源观点存档；策略名字不能证明实际净 Greeks。

Vega 表示价格对隐含波动率变化的敏感度，Theta 才是对时间流逝的敏感度；IV下降和时间衰减是不同因素。若用户另外请求期权分析，需要最新期权合约、到期、乘数、结算币、买卖腿、可成交报价和 Greeks；此工作台未接入这些输入，也不根据旧聊天持仓自动生成移仓/卖腿指令。个人持仓信息不得写进公共 README 或 snapshot。

### 10.3 作者昨日复盘与宏观观点

来源复盘只能标 `source_claim_unverified`，除非有独立具名行情、触发时点和完整路径证据。不能将“触发后涨至X”计成本项目收益、真实交易或胜率。原页政策叙述也不自动成为已核实新闻；网页未接入事件日历时，必须提示“未接入不代表没有事件风险”。

## 11. 每日潜力区：设计规则不等于已运行监控

### 11.1 入库与阻断

- 提取“今日潜力观察”“昨日复盘”“市场门控”；写“无”也要清空当日观察，不能沿用昨天。
- 保留原标签、兜底/探顶类型、价格、资料日、编辑/核验时间和来源文本。
- 原页没有交易所、现货/永续、报价币、确切资产身份时：`venue_mapping=assumed`、`symbol/venue=null`、`mapping_status=unverified...`；不因 Binance 上有同名字母就选合约。
- `valid_through = source_date + 1 个自然日`；再往后过期，停止触发。它是项目有效性规则，不是作者保证价位有效至该日。
- 市场不稳时最高 `observe_only`，不是自动操作开关。
- 11月7日 AIOT 0.112 为来源兜底观察价，映射未核实，**未请求行情、未激活监控**；旧ICNT复盘仅归档作者声称。

### 11.2 有权限且映射确认后才可落地的保守设计

以下来自原研究设计，不是当前静态网页已经执行的实时监控：

| 状态 | 规则摘要 |
|---|---|
| 等待 | 距离区间超过0.5 ATR，仍在预期测试一侧 |
| 测试 | 高/低进入区间±0.5 ATR；单根插针不算站稳 |
| 结构观察 | 探顶至少两根闭合5分钟K站上，或上穿后回踩不破；兜底仍保持上方 |
| 失败 | 探顶触线后1–3根闭合K跌回或回落超过0.5 ATR；兜底跌破超过0.5 ATR |
| 重新分类 | 兜底跌破后重新站回，改为“探顶区重新收复观察”，不能继续称原支撑有效 |
| 过期/阻断 | 超过来源次日、报价过期、映射不明、零成交或未闭合K，不升级 |

TR 的通用定义为 `max(H−L, abs(H−C_prev), abs(L−C_prev))`。历史示例用14根5分钟K的 ATR；上线监控前仍须固定平滑方式、完整闭合窗口、报价时间、成交/标记价口径，并写测试，不能从一个历史示例宣称已有全量监控实现。ATR只定义噪音/失效观察带，不用于推算爆仓杠杆或自动双开/续仓。

## 13. 图表、光标与新鲜度的实际语义

- 当前[chart.mjs](../../portal/vendor/otc/chart.mjs)为原生模块/SVG；三面板使用同一自然日横轴、各自线性纵轴，不用指数拼K线，不做指数归一化收益。
- 价格轴用可见高低值；场外轴强制包含1000、爆破轴包含0/200，并在极差上下各留10%余量。缩放会改变视觉斜率，不能据截图跨品种比较“资金速度”。
- 周期底色来自当天点；没有当天场外点就斜纹、曲线断线。价格缺失不造K线，股票非交易日也可能为空。
- 场外<1000和爆破<200是彩点/徽标；新下穿是向下三角；质量节点/周期切换是圆点；旧标记待核为空心菱形。“逼近”标记直接来自作者。
- `atDate()` 取 `date <= 观察日` 的最后一个点（依赖points已升序）；没有则null。右侧可以显示最近历史记录并明确日期，不能显示未来点。
- 光标 tooltip 使用**那一天的精确点**；缺页显示缺失。因此右侧最近记录和tooltip空值可以同时出现，这是有意区分，不是需要补齐的bug。
- 最近日期为 `max(snapshot.dataDate, 全部公开价格latestDate)`，不是所选资产自己的最新资料日；价格比指数新时，必须保留指数缺源提示。
- 默认90天，可选30天/1年/全部；鼠标联动日期、OHLC、周期天数、场外、爆破；点击锁定、方向键/滑条逐日查看。
- 自动价格模式按**整个资产序列**优先具名公开bars，否则整条用参考归档，不逐日拼接两个来源。公开源失败但还有旧bars时显示旧日期和错误。
- 页面启动读取 snapshot；可见时每300000ms刷新**价格文件**，初次加载参考价格。**不会每5分钟自动重新读取场外snapshot**，新原页发布后需刷新页面。
- CSV限制2MB、最多10000条，需 `date,open,high,low,close`，校验真实日期/正数/高低范围/重复；不是全功能带引号CSV解析器。结果仅内存，不上传。

### 两种新鲜度提示不要混淆

`/otc/` 主横幅：最新资料日早于新加坡今天，就提示缺最新原页、仅历史观察；计划也提示不是今日数据。

共享导航状态由[门户构建器](../../portal/build_site.py)另行生成：场外 `asOf` 使用资料日 `23:59:00+08:00` 的展示锚点，门槛48/96小时。它不是页面真正发布时间，也不是放宽 `/otc/` 当日缺源规则。导航未变红不代表今日场外已到齐。

## 14. 收到下一份用户原页时怎么更新

### A. 冻结基线、读取原页

1. 查看工作区状态和远端main；不reset、不覆盖其他人的未提交更改。只读比较本次相关路径。
2. 获取当前仓库与正式站snapshot，核对版本、字节/哈希、资料日、记录数。若仓库已经更新而站点仍旧，先弄清部署进度，不能用旧站点覆盖新main。
3. 私有保存原页响应，检查读取是否完整/被截断/有未知块。无法读取就报失败，不从摘要猜数字。
4. 核验日期与年份。日期有冲突先请用户确认；明确的正常页无需重复询问。
5. 独立抄核各行 asset、场外、爆破、周期、计数和单位，并核对潜力/昨日复盘/资金/市场门控。核对的是原文，不是两次运行同一个解析器。

### B. 生成审核候选

1. 计算同源日差及间隔；标出缺页、计数异常、来源值异常和新增资产。
2. 分开算低位状态、新阈值事件、质量节点；严格处理等号、换源、缺页和周期切换。
3. 根据本轮首日/最近确认节点做质量比较，记录基准date/value/type、百分比、前后评级及理由。
4. 保留旧候选、旧异常；当日正常递增不等于旧计数已修正。资金差异、产品映射不明不得自动消除。
5. 构造当日公开points和day；只从白名单字段生成，不复制整篇原文。私有候选记录公开基线SHA-256，防止误用另一个基线。

### C. 写入与公开增量

**有原研究工作区时**：先备份需要修改的账本；审核特定日期脚本的无写入预演，再只执行一次写入；追加CSV、candidate、latest、核验日check、潜力区文件。不可重新执行旧日期 `--write` 或直接把日期常量替换后运行。
