## 1. 开始前建立同一基线

1. 取得 `https://github.com/blikeywang/kezhou` 最新main，记录commit；保留用户未提交修改，优先用独立开发检出。不要在调度器的可重置clone里开发。
2. 读本目录全部四份文档和对应源码。根目录旧`CLAUDE_CODE_RUNBOOK.md`是早期刻舟建站手册，其“新建仓库/前端唯一真源”规则不适用于已有TailTrend。
3. 读取latest/index/audit，核对数据日、运行日、hash、活跃epoch。全站部署成功不能代替行情更新成功。
4. 先跑现有测试，记录基线；有失败先分清依赖/环境与真实回归。
5. 解释本次改动属于文案、数据刷新、引擎规则还是数据schema；改变规则/口径时显式更新研究版本和必要迁移策略。

|---|---|---|
| P0 | Git与线上latest均停在2026-08-12；源码已有Mac调度 | 查登录/权限/安装/任务日志和真实交易日。证明连续新日落盘与发布，不能只看代码已存在 |
| P0 | refresh不滤未完成日线；FRESH只与本批最大日期比较；complete只检查异常和数量 | 使用明确的已收盘交易日与完整字段验证；提前收市、休市、全池旧数据、INSUFFICIENT分别有结果 |
| P0 | 财报请求失败只console.warn；当日事件可能因查询起点晚于dataAsOf而漏掉 | 增加事件覆盖状态/可知时间；未知不能默认为已排除事件；用失败和跨日用例验证 |

| P1 | 下沿无锁立即收复分支不用5日；周线含本周未完成周；trend原边界长期不重置 | 把研究选择显式化，针对边界构造测试；不要误当作旧文档已承诺的规则 |
| P1 | 止盈比例、趋势预留、“下一高周期尾部”只有预算或文案，无持仓状态机 | 若要回放，先定义成交/分批/同日顺序/风险占用；不要把文字直接算成既有收益 |
| P2 | ATR对照无独立递推；priority未校准；漏判统计只覆盖OBSERVE且running无固定截止 | 定义可比较分母/窗口，不把同日对照当完整策略A/B，不据10日样本寻优 |
| P2 | OHLC清洗不全、退化区间缺兜底、CSV简单拆分、均额可只基于部分有效日 | 补数据契约验证及明确降级，保留坏行/缺日诊断 |

与历史评审的四个重要口径差异：

- “每个收复都稳定5天”不成立；WMT示例走`STABLE_MAP_RECLAIM`。
- “所有边界完全不包含当前日”有例外：结构破坏后用当日完成数据重建新锁。
- “风险按0.24%袖套直接裁剪”不准确；代码先裁剪总想法，再60/40分配。
- “所有风险字段已进入公开审计”不成立；账户回撤、真实组合/集群热度、人工覆盖仍缺失。

## 4. 更新流程与验收

### A. 仅更新行情

检查目标日已收盘、Longbridge行情和事件获取成功、旧日文件存在情况；运行刷新后检查完整性，再运行现有测试。禁止用今天的数据补造成8月当时就有的影子信号。历史重建若需要，单独标记为replay/backfill并存放独立路径。

每次提交应能回答：哪些数据日新增、哪些缺跑、哪些symbol降级、状态为何变化、使用哪一版引擎和参数、审计的T+1是否真的连续且可成交。

### B. 修改算法

先写明预期变化和一个能触发差异的最小行情路径；补对应回归，不只测试函数返回字段存在。锁定回放epoch、成本/事件可知性后跑旧/新版本对照。修改引擎/参数之前确定旧状态记忆和审计如何隔离，不修改既有快照来使新测试好看。

### C. 推送与发布

常规开发用 `codex/` 分支，审查diff后只暂存本次路径。main可能因其他项目或数据机器人并发变化；重新fetch、检查新增提交并整合，禁止force push和覆盖其他模块。用户已授权的发布方式按当次指令执行，分支保护若要求PR则走PR。

GitHub回读文件/commit，数据或页面更新再核对Pages工作流和公开网址。纯文档更新的验收重点是文件内容与链接，不能因为随后的定时部署运行就声称刷新了行情。

### D. 适用验证命令

```bash
node --test portal/test_tailtrend_engine.mjs tools/scheduler/test_refresh_runner.mjs
python3 -m unittest portal.test_portal
git diff --check
```

引擎/页面改动另外检查：中部/候选/过期/事件/借券未核验均0股；模块不能切换绕开；允许候选预算满足容量；移动端详情与桌面一致；无JS静态回退明确数据日。全站工作流要求的其他测试以最新YAML为准。

## 6. 建议接手顺序

1. 恢复并验证真实数据、事件与目标交易日链路；修正失败审计和时效一致性。
2. 建立缺日/同日修订/参数迁移规则，再累计连续10个工程影子日。
3. 建2–3年逐日递推回放，保存私有数据版本与公开派生结果；加入费用/滑点/公司行动、退市及样本外区分。
4. 报告候选→接受率、假收复、趋势持续、错过行情、风险约束分布；说明样本量、观察窗口和不确定性。
5. 有证据后才评估尾宽、确认速度、退出规则或扩池。盘中探针及自动下单仍属于后续独立范围。
