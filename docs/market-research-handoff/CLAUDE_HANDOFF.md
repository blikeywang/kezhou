## 首次接手核对清单

1. 确认当前日期、市场交易日、用户是要“读历史/解释”还是“采集更新/发布”。不要自动延续上次到期合约、风险预算或方向判断。
2. 确认 kezhou remote、分支和未提交改动；只修改任务路径，不覆盖现有门户/其他 agent 的更改。
3. 若有本机权限，检查 PROJECT_ROOT、只读外部源、生产脚本与运行时依赖；不读取秘密文件的值来“验证权限”。
4. 重新盘点历史。交接时本机早晚报到 2026-09-21，公开 JSON 索引 57 日；这个缺口不在本次补齐。
5. 核对 `otc_source.mode=user_provided`；CSV 缺失不得走工作簿旧种子；旧 HTML 复制器不得泄露完整私有报告。
6. 从当时配置读 freshness/配额，不硬编码本文作为永久真值。分数≠概率、missing≠0、导出时间≠数据日。
7. 本包测试命令：在本目录执行 `python3 -m unittest discover -s . -p 'test_*.py' -v`。
8. 日报生产代码测试在 PROJECT_ROOT 内按对应模块执行：`python3 -m unittest discover -s tests -p 'test_*.py'`。测试是否需要依赖/临时文件以当时实现为准，不用正式数据目录做无保护的回放。
9. 公开导出测试在 kezhou：`node --test tools/daily-trade/test_export_public.mjs`；门户回归：`python3 -m unittest portal.test_portal`。本次交接只增加文档/离线公式，不声称整套生产调度或网站端到端验证通过。
