# 已知限制与Claude接手优先级

核对基线2026-11-08，来源为本项目源码、配置和现有测试；**本次只记录，没有修改这些生产逻辑**。本页P1/P2是研究可靠性优先级，不是收益或市场风险评级。40项已有测试通过不代表下列缺口已解决。

## P1：先解决，再谈可执行性或可交易回测

| 问题 | 当前行为 / 影响 | 接手验收 |
|---|---|---|
| 策略定义不一致 | 固定`-1/0/+1`翻仓，重复同向信号忽略；不是用户原先每次加1股 | 两个策略独立命名、配置与测试；明确翻向平旧仓及新仓数量 |
| 无不可变实时S1事件流 | 清单/历史图不能恢复已删除B/S的首次可知时点；同日版本可能覆写 | append-only接收、修订/撤回、图锚点日志；按实际可知时刻回放 |
| 同步来源优先级 | `syncSignals`先重写同日CSV，随后preserve函数主要保状态，未保证保住用户已接受同日行 | 给“用户清单更完整、旧HTML同日较少”做回归测试；不得用较弱来源覆盖 |
| 回测时间边界 | 下一根缓存日K未必是交易所下一交易日；缺口/未闭合当日K/未来信号元数据有风险 | exchange calendar、bar close、available_at联合校验；未来事件与缺口强制阻断 |
| 冲浪尚未接回测 | 冲浪/13点/风险筛选独立于旧一股回测 | 同一交易假设、事前参数，比较未筛选与筛选策略，包含拒绝/缺失样本 |
| L1字段不兼容 | 接入层输出如`L1 84 · #4`，下游用严格`== 'L1'`，可能全部漏掉 | level、score、method拆字段；真实适配器输出进入最终门控集成测试 |
| 账户并非完整硬门控 | 当前入场状态可在账户缺失时仍为conditional；风险倍率0也不保证状态同步降级 | 单一资格函数；账户缺失/失败/过期与预算0均不可进入执行候选 |
| 13买点外部源码缺失 | 原相对导入路径不可用，13套内部公式无法核验；接入fallback也非处处闭合/RTH过滤 | 恢复合法只读依赖、固定版本；每个provider统一闭合/RTH/量能契约 |
| 期权旧日标签不等于历史回放 | `--date`不限制最新接口；日K响应函数也缺完整截止/闭合过滤 | 所有价格/链/OI带effective_at与available_at；历史跑法与实时采集彻底分开 |
| “次日ΔOI”口径过宽 | 可取最近更早报告，不保证相邻OI结算日；少量可比合约也可能置ready | 保留两边OI统计日，限定可比合约与相邻结算日，报告覆盖率而非单一ready |
| 陈旧/未来数据门控不一 | 趋势评分没有内部日期门控，宏观旧非空值可能继续触发，部分未来日期算最新 | 统一按数据频率/交易所判断；未来日期拒绝；过期不参与当前触发 |
| 盈利、资金与保证金易混 | 旧收益分母是峰值日终毛敞口；佣金/保证金是历史模型；未完整处理借券和待执行篮子 | 区分PnL、资本回报与保证金；验证当期券商政策、借券、公司行动、结算与日内路径 |

对应详细证据：[核心导入](CORE_PIPELINE.md)、[S1/资金公式](S1_SURF_BACKTEST.md)、[期权时间/OI](OPTIONS_AND_FLOW.md)、[风险/入场门控](RISK_AND_ENTRIES.md)。

## P2：数据协议、显示和可维护性

- **CSV去重不是版本控制**：`(date,action,symbol)`原始键无法吸收同键字段修订；别名归一分散，不可把原始条数直接当独立标的数。
- **旧手册的计分与代码不同**：手册仍描述两项；当前实际三项是标的趋势、大类趋势、场外。分数只是一致度，不能叫胜率。
- **OTC历史schema冲突**：通用JSON importer的扁平行与现有中文历史账本不同。日期特定intake脚本也不是统一评级引擎。应先定义schema/version再迁移，保留原历史。
- **跨年问题**：场外旧`月.日`历史和网页重建硬编码2026；手机锚点年份也可能误解旧记录。迁移为ISO日期，并测试跨年、月单位和缺页。
- **潜力区监控不完整**：报告消费已有monitor JSON，不能把页面上的ATR/闭合K规则文案当成自动实现的行情状态机。需独立定位并验证监控生成器、交易所映射和时间戳。
- **保护单覆盖过弱**：仅凭instId存在，不足以确认方向、数量、状态及reduce-only；应逐仓位验证覆盖，不把“有订单”当“有足额止损”。
- **缺口压力使用旧报价**：Longbridge扩展时段陈旧/未知时间报价仍可能进入账户估算；应强制新鲜度并披露基差/滑点不包含。
- **宏观单位与篮子**：RPONTSYD单位应重新对照官方序列；资本开支目前无完整公司去重、最新季度与QoQ重算约束。慢指标缺完整自动采集，不能用视频历史数字填今天。
- **完整链/Greeks声明偏宽**：部分标志只校验容器或OI存在，不证明所有Greeks、到期和行权价完整；输出逐字段/逐到期覆盖率。
- **事件响应与收益不同**：从信号前收盘到观察日的变动可能包括信号当天已完成涨跌；必须与可知后成交收益分开。
- **异常度的绝对值影响**：绝对z-score使成交量骤降也可高异常；排序不是方向强度、概率或全市场机会排名。
- **手机显示代理**：Desk方向/部分标题硬编码、缺FOP P/C可能形成偏正内部值、多个期权面取最大report_date掩盖旧项、failed模块仍可影响集合与熵。应以数据状态驱动显示并补合成测试。
- **旧结果文案硬编码**：三份回测/资金脚本中有历史日期、计数、费用和解释。动态结果变了不代表静态结论自动变对。
- **同日输出会覆盖**：报告、history中的部分同日期文件不是不可变事件日志；重新运行必须先归档输入/输出及版本。
- **发布不等于脱敏充分**：sanitize函数不是秘密扫描器；私有手机端含账户数字的快照不能公开。公开文件必须白名单而不是“全项目git add”。

## 未验证、不可由本仓库推出的结论

1. S1确切底层是否ZigZag+RSI，以及是否人为改标记：现有相似图和消失描述不能证明源码，也不能自动归因于主观操作。应比较带真实时间戳的前后同源快照和固定candle ID。
2. 原策略真实收益、冲浪筛选后的收益改善、当前账户应备多少美元：本次未重新获取市场/账户数据，不能给新的数值结论。
3. 所有历史标的现在仍以同一证券身份可交易：需合约ID、交易所、公司行动和代码复用检查，不能只匹配ticker。
4. 公开代码文档能直接完成IBKR批量下单：没有订单生成器/执行客户端，研究订单明细也不是交易授权。
5. 13买点所有公式、供应商接口当前健康度、现行费率/权限、所有定时任务正在运行：本次均未验证，不许暗示已验证。

## 建议增加的验收样例

| 样例 | 必须观测到的结果 |
|---|---|
| B、B、S、S、B | 固定仓位与累计仓位产生不同账本；每笔数量可追溯 |
| B后来从旧K线消失 | 保留曾收到的B和撤回时间；不能从回测中无痕删除 |
| 周末/假日/停牌/数据断档 | 各自正确映射可交易时点；未知执行日不得随意后移 |
| 报告日早于某条行情/信号 | 不让未来信息进入指标或成交 |
| 相同价不同复权/分拆 | 拒绝直接拼接；公司行动和持股数量一致 |
| 同日完整版后收到缩减旧HTML | 已接受原文保持可追溯；明确选择哪一版本 |
| `L1 84 · #4`、账户缺失、预算0 | 先正确解析L1，再由账户/预算门控降级，不误放行 |
| ΔOI比较跨周或合约换月 | 不冒称相邻结算日确认；给出不可比原因 |
| 缺P/C、未来日期、旧宏观 | 不凭默认0给看多/最新标签，不触发陈旧条件 |
| 同日期重跑与远端并发更新 | 保留旧审计版本；发布拒绝错误父提交，禁止强推 |

每个修复先增加会失败的测试，再改实现、记录规则版本，最后用固定输入比较前后差异。用户只要求更新数据时，不擅自修策略或调阈值；发现不可靠就降级并报告。

研究用途，非投资建议。
