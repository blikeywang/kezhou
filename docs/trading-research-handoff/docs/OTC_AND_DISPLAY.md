# 场外分支、公开日K与手机显示计算

基线2026-11-08。这里说明研究数据如何进入网页，**不把网页颜色、历史评级、阈值或相位当交易信号**。场外原始指数不是本项目由行情推导的量；用户来源给什么就先保存什么。

## 1. 原页入库与版本

来源是用户主动提供的Notion原页/文件/文本。读取时核对正文日期、页面信息、品类列表、今日潜力、昨日复盘、市场门控、资金总量与细项。正文日期与链接标题/访问日冲突时明确保存`date_resolution`，不能自动按当前日期写入。

早期手册写44个核心品类；品类集合后来有扩展。**不要把44硬编码为永远完整**。应对照当前原页、最近已验证的资产集合和显式新增/缺失列表；新增未核实产品保持身份未知。

典型日级审计目录为`outputs/otc-chart/intake-日期/`，保存候选、前态、已发布基线、独立验证、预览和发布验证。本次读取的2026-11-07验证脚本是日期特定审计，不能不改日期就拿来做通用更新器。

## 2. 差值、周期与质量

```text
场外Δ = 当前来源场外值 − 前一可比来源记录场外值
爆破Δ = 当前来源爆破值 − 前一可比来源记录爆破值
步进% = (当前节点场外值 / 参考节点场外值 − 1) × 100
```

每个Δ必须保留比较日期和相隔天数；缺页后的Δ是跨多天变化，不叫“昨日变化”。上游报告Δ与实际差值不符，保留原数并提示，不偷偷改写。

周期“进场/退场”和周期计数来自原页。计数重复、跳变、日期矛盾要列异常。月度品类保留“月”，不能改为“天”。质量评级是项目研究台账，不声称供应商保证。

质量节点比较必须限定**同一周期**。采用最近已记录且确认的同周期节点；没有历史节点时可用周期首日作比较基线，但首个节点通常仍不足以升级为“优质”。进场节点场外改善/退场节点场外下降仅是方向性比较，不自动推出上涨/做空获利。

目前质量演化分散在日级intake脚本与历史账本中，`build_snapshot.py`主要沿用已写入质量，并不从零重算所有历史评级。接手时需要整理成一个版本化统一状态机，不能声称已有单一权威通用评级引擎。

## 3. 网页快照节点的精确条件

控制实现：`outputs/otc-chart/build_snapshot.py::main`与`append_to_verified_baseline`。

- 原页记录先保留；2026-09-22获准参考站归档仅补缺日期。同日不同值在`referenceConflict`记录，Notion优先，不回写研究CSV。
- 当前重建模式把旧CSV的`月.日`解释成2026年，并显式拒绝其他年份的latest。跨年需要迁移完整ISO日期，不能直接继续拼接。
- 原页历史Δ核对允许0.11的差值容差，超过则加警告。
- `adjacent`定义为**相邻自然日差恰好1天**，不是交易日；`same_source`要求`sourceKind`相同。
- `transition`记录前后周期标签变化；`gapBefore`记录不相邻。
- 场外跌破1000、爆破跌破200：前值`≥阈值`且现值`<阈值`。相邻且同源才记事件，否则只能记候选。
- 进场节点“跌回200”：同源相邻、同周期、前爆破`>200`、现爆破`<200`。等于200不满足这个严格节点条件。
- 退场节点“负转正”：同源相邻、同周期、前爆破`<0`、现爆破`>0`。等于0不满足。
- 旧账本有关键节点但上述条件不满足，保留`unconfirmedNode`，不跨缺页补确认。
- 参考站价格独立文件保存，标记市场/时区/复权未披露；不与具名价格拼接。

增量`--baseline`模式核对前一已发布快照SHA-256、schema、白名单字段和总数，确认旧points/days前缀完全不变后追加。它是保护历史的机械检查，不能取代新候选的独立算术验证。

## 4. 网页分类与条件文案

`outputs/otc-chart/site/engine.mjs`的`tier`按以下顺序：

1. 没有记录→missing。
2. 进场、质量优质、场外≥1000、爆破>0→focus。
3. 质量劣质，或场外<1000，或爆破<0→avoid。
4. 进场、计数≤3且单位为天→new。
5. 其他→watch。

这里“劣质”是周期研究质量标签，不是对公司的基本面评价。`planFor`始终返回`executable:false`，并列价格结构、止损、独立确认、账户许可缺失。历史日期查询用`date≤asOf`的最后一条记录，同时显式提示当日缺页；这不是可交易回测。

CSV手工价格导入要求`date,open,high,low,close`，正有限数、OHLC高低一致、日期唯一，最多10000行；只在浏览器内存使用。

## 5. 公开价格与发布

`update_public_prices.py`只映射白名单，不根据名字猜测新产品。

- Binance：`SYMBOLUSDT`现货，UTC日线，只接受供应商closeTime早于当前时刻；保留旧记录并按日期合并，默认从2025-01-01起或最近14根重叠刷新。
- Yahoo股票：必须返回匹配代码且类型EQUITY；按交易所时区，正规时段，原始OHLC、不按复权收盘缩放。同会话日线要等供应商正规收盘时间后20分钟才接受。
- 单源403/429/451后本轮后续同源请求跳过；失败保留旧bars、原updatedAt、原latestDate并写错误。
- 长桥冲浪使用前复权日K；此处公开价格是另外的数据产品。不能无说明混用两者算收益。
- `copy_to_traderhome.py --snapshot-only`只复制场外快照；完整复制另含UI和公开价格。纯数据更新必须保护云端已刷新的prices，不能用本地旧文件覆盖。

手册记录的公开价格定时计划是UTC00:35/06:30，浏览器可见时5分钟检查。它是配置/文档计划，不是本次对GitHub Actions健康状态的实时检查。新的发布必须另核对实际工作流与远端父提交。

## 6. 每日潜力区：规则说明与实现边界

`daily_trade.py::validate_potential_zones_payload`校验来源日、zones数组、`top/support`类型、正level及asset/symbol。早报把monitor按大写symbol/asset匹配，且必须满足`monitor.source_zone_date == zones.data_date`；不匹配只显示原始区间并提示缺行情观察。`distance_pct`、`mark_price`和状态为输入值，报告层并没有重新计算它们。

手机页面展示的研究规则为：距离超过0.5 ATR等待；进入±0.5 ATR测试；至少两根闭合5分钟K站上或上穿回踩不破才作结构观察；触线后跌回或兜底跌破0.5 ATR作失败；兜底跌破后再站回仅重新分类为探顶观察。市场门控不稳和映射假设还需限制升级。

**这些文案不是自动行情状态机已运行的证据。** 本次核对的核心scripts中，主要是校验/消费已有monitor JSON，没有发现统一负责抓取具名5分钟行情、计算ATR并生成上述所有状态的日常入口。不得从页面文字推导出“系统已逐标的实时监控”。接手时应定位原监控产物生成过程，固定ATR窗口/算法、闭合时点、交易所、触线定义和过期规则，再补测试；缺少生成器时保持缺失，不能自行补造状态。

## 7. 手机“动力学/热力学”仪表公式

控制实现：`scripts/build_mobile_snapshot.py`。这些是人为可解释仪表，不是物理模型或回测概率。

### 7.1 方向值与来源权重

显示温度映射与方向评分不同：`沸1、热0.8、温0.5、平0、凉−0.5、寒−1`。

默认模块权重/方向：

| 模块 | reliability（人为权重，非正确率） | direction |
|---|---:|---|
| 场外 | 90 | 场外美股market_bias.score |
| 潜力区 | 55 | failed/failed_reclaim为−1，否则0；不参与NQ/ES总相位 |
| 趋势 | 80 | 美股显示温度映射 |
| S1 | 70 | 完整清单时`(Buy−Sell)/(Buy+Sell)`；Buy-only不计算净宽度 |
| 13买点 | 可用60，否则0 | 固定0，只呈现候选 |
| Desk | 65 | **当前固定−1，未根据每日摘要动态判断** |
| 期权 | 70 | FOP P/C与SPY/QQQ P/C启发式映射，见下文 |

FOP平均P/C<0.8→+0.5，>1.2→−0.5，其余0。SPY/QQQ可用P/C均值<0.8→+0.5，>1.1→−0.5，其余0。有ETF P/C时两者均值，否则用FOP值。没有FOP P/C时当前分母保护可能得到0并形成偏正内部方向，必须与failed/覆盖一起看，不能当真实看多证据。

### 7.2 新鲜度与亮度

```text
age = max(0, 报告锚点自然日 − 来源日)
freshness = 缺日期/本次失败时0，否则max(15, 100 − 20×age)
light_i = abs(direction_i) × reliability_i × freshness_i / 100
signed_i = direction_i × reliability_i × freshness_i / 100
```

亮度≥50为lit，≥25为glimmer，否则dim；失败或权重0为dark。旧数据衰减到15而不是归零；未来日期age被钳为0，另需校验。发布锚点目前取`data/status.json.updated_at`日期，不一定等于输入真实数据日。

参与集合F：`focusEligible && reliability>0 && abs(direction)>0.01`。代码没有额外把failed模块从集合排除；它的亮度可为0，但仍可能影响集合数量和熵，属于已知显示限制。

```text
T = Σlight_i / max(1, |F|)                     平均亮度（temperature）
Force = Σsigned_i / max(1, |F|)                有符号平均亮度
Coherence = abs(Σsigned_i) / Σlight_i ×100     无亮度时0
RiskPressure = Σ(负方向light_i) / Σlight_i×100 无亮度时0
Entropy = −Σ(p_k ln p_k) / ln(3) ×100         三态分布，无/单态为0
IgnitionCount = 全模块中light≥50的个数
```

三态按direction>0.12为正、<−0.12为负、其他中性。相位规则按顺序：T<25→低能等待；熵≥70且Force<−10→中温高分歧/防御；熵≥70→高分歧；Force>15→顺向升温；Force<−15→防御降温；否则中性蓄能。

### 7.3 显示层已知限制

- Desk方向及部分主标题是硬编码防御文案，并未每日从数据推导。
- 期权模块新鲜度取多个子面report_date的最大值，可能掩盖其中一个面实际较旧。
- 旧场外历史月份/日期用锚点年份解析，跨年存在错配风险。
- 清单宽度按原始CSV计数，别名重复若未预先清除会影响展示。
- `sanitize_public_value`删除路径/凭据变量名，但不能保证删除任意真实密钥；它不是泄密检测器，也不授予账户数据公开权。
- 本机私有手机快照可含脱敏账户数字；不能因为“脱敏”就把该snapshot上传到公开kezhou。本次交接只上传方法文档。
