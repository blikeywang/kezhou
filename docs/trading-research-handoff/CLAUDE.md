# Claude 接手约定

本文件是用户要求编写的接手说明，适用于本研究流程；不是券商交易授权。

## 第一次接手

1. 读本目录 `README.md` 和 `docs/KNOWN_LIMITATIONS.md`。
2. 在用户本机定位“猴认知分析”项目，完整读该项目当前 `AGENTS.md`、`WORKFLOW.md`。本交接包是2026-11-08基线，不能替代后续新增的用户约束。
3. 比较 `source_inventory.json` 中的路径与哈希，确认你运行的是哪一版。不要把 kezhou 根目录误当成本机研究根目录。
4. 确认用户本次是在要“更新数据”“修改策略”“重算回测”还是“发布文档”。前者不自动授权后三者；尤其不要在更新当天数据时顺手改阈值。
5. 先运行离线测试，核对外部依赖和输入日期。不要通过读取或打印 `config/private.json` 来探测环境。

## 不能突破的边界

- 不下单，不自动清仓，不把研究条件文件当订单。
- TrendTrader密钥只允许由程序从环境或本机私有配置读取；OKX只用Read权限，禁止Trade/Withdraw。
- 账户快照、凭据、券商原始K线、付费原文不进入公开GitHub、网页或日志。
- 场外指数/每日潜力区只消费用户主动提供的原页、文件、文本。不要去Claude历史场外表或其他来源补当天缺页。
- 2026-09-22授权的参考站历史归档是有日期的特例，不是允许持续抓取所有外部场外来源。
- 两个外部参考工程只读：Claude旧资料目录、13买点工程。不要修它们来绕过本项目限制。
- 新研究产物留在本项目 `data/`、`reports/`、`outputs/`；历史与审计记录不要覆盖删除。
- 只收到Buy时，Sell为未知；必须保留 `buy_only_as_received`，不能构造“0 Sell”。
- 缺行情是 `missing_price_data`，不是“非冲浪”；成功扫描零候选也不等于失败。
- 相邻清单都含B只能确认清单保留，不能证明同一根K线上的箭头未重绘。

## 更新一份S1时

保留原文 → 核验日期和代码 → 写入审计intake → 合并标准CSV → 标明覆盖 → 冲浪 → 13买点 → 有界期权验证 → 报告 → 校验 → 按获准范围发布。

逐项输出来源日、行情截止日、实际运行时间、缺失原因、下一确认和失效条件。发现日线大涨后才出现B时，不把当天已经完成的涨幅计入可交易收益。

## 你必须先处理的工程问题

先看 `KNOWN_LIMITATIONS.md`。优先修复：L1字段协议、账户硬门控、交易所日历与时间截止、严格相邻ΔOI、逐次加仓策略与现有翻向回测的区分。每项修改都要有失败样例、修复后的测试、策略版本号和旧结果保留。

若用户只让更新数据而没有授权修规则：如实报告限制，按更保守状态输出，不自称问题已修复。
